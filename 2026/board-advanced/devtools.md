# DevTools の操作手順

この講座で使う DevTools の機能をまとめています。
手順は Chrome のものです。
Firefox の違いは各節の最後に書いてあります。

## 開く

`F12` を押すか、画面を右クリックして「検証」を選びます。
Mac は `Command + Option + I` でも開きます。

StackBlitz のプレビューは右側の小さな枠です。
枠の中を右クリックして「検証」を選ぶと、プレビューではなく StackBlitz 自体の DevTools が開いてしまうことがあります。
プレビュー右上の「新しいタブで開く」でプレビューだけを別タブにしてから開くと確実です。

## Network タブで通信を 1 本ずつ見る

「Network」タブを選び、そのままページを再読み込みします。
読み込みの途中で開くと、開く前の通信が載りません。

| 列 | 読み方 |
| --- | --- |
| Name | 通信先のパス。`posts` や `events` が並びます |
| Status | 200 なら成功。`(pending)` は返事がまだ届いていない |
| Type | `fetch` / `eventsource` / `document` など |
| Time | 返事が返ってくるまでにかかった時間 |

上の `Filter` 欄にパスの一部を入れると、そのパスの通信だけが残ります。
`posts` と入れると、画像や CSS の読み込みが視界から消えます。

<!-- screenshot: network-polling.png -->

### ポーリングの様子を見る

10 秒ごとに読み込む状態では、`posts` の行が 10 秒ごとに 1 本ずつ増えます。
中身が同じでも、新しい投稿がなくても増えます。

行が増えていくこと自体がポーリングの姿です。
間隔を 1 秒に縮めると、増える速さがそのまま 10 倍になります。

### SSE の接続を見分ける

`EventSource` でつないだ通信は、Type が `eventsource` になり、Status が `200` のまま Time が伸び続けます。
返事が終わっていないので、いつまでも受信中のままです。

投稿が増えても、この行は増えません。
1 本のままです。

<!-- screenshot: network-eventsource.png -->

## EventStream タブで届いたイベントを 1 件ずつ見る

Network タブで `events` の行をクリックすると、右側にタブが並びます。
その中の「EventStream」を選びます。

| 列 | 中身 |
| --- | --- |
| Id | イベントに付けた通し番号。付けていなければ空 |
| Type | イベントの名前。付けていなければ `message` |
| Data | 送られてきた中身 |
| Time | 届いた時刻 |

投稿が届くたびに、行が 1 つ増えます。
画面の一覧に出ないのに行だけ増えているなら、届いてはいるがブラウザ側の処理でつまずいています。
行も増えていないなら、そもそも届いていません。

<!-- screenshot: eventstream-rows.png -->

ハートビート（`: ping`）はこの表に出ません。
コメント行はイベントではないためです。
接続を保つためだけに流れているので、出ないのが正しい動きです。

Firefox も同じ位置に「EventStream」があります。

## サーバーを止めて、通信が切れたときの動きを見る

自分のサーバーにつないだ状態で、ターミナルで `Ctrl + C` を押してサーバーを止めます。

<!-- screenshot: network-reconnect.png -->

次のことが起きます。

1. つないでいた `events` の行が、止めた時点で終わって赤くなる
2. 数秒後、ブラウザが自分で新しい `events` の行を作ってつなぎ直そうとする
3. サーバーがいないので失敗し、その行が赤くなる。数秒おきに繰り返す

`npm start` で起動し直すと、次の試行でつながります。
切れている間に投稿されたものは届きません。

つなぎ直しはブラウザが行うので、こちらで書くコードはありません。
取りこぼしのほうは、こちらで手を打たないと埋まりません。

ブラウザの機能ではなくサーバーの停止で起こすので、Firefox でも手順は同じです。

### throttling の Offline では接続は切れない

Network タブの throttling を `Offline` にしても、すでに張れている SSE 接続は切れません。
`Offline` が落とすのは新しいリクエストだけで、開いている接続にはデータが流れ続けます。
`navigator.onLine` は `false` になり、`fetch` も失敗するので、Offline の設定自体は適用されています。
Chrome 150 で確認した挙動です。

つなぎ直しを見せたいときは、上のようにサーバーを止めてください。
`Offline` が使えるのは、ポーリングのように毎回新しいリクエストを出す通信です。

## イベントが来ないときに見る順番

1. Network タブに `events` の行があるか。無ければ `EventSource` を作る行までたどり着いていない
2. その行の Status が 200 か。赤ければ URL か部屋 ID が違う
3. EventStream タブに行が増えるか。増えないならサーバーから流れてきていない
4. 増えているのに画面が変わらないなら、受け取ったあとの処理を Console タブで見る

Console タブに赤い文字が出ていないかは、どの段階でも先に見てください。
